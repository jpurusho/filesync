# M3.5 — Quick-send (FR-SM-6)

**Status:** complete
**Owner model:** Opus (protocol/session design)

## Goal

Profile-less one-shot file/folder transfer to a paired peer. Reuses M3's TLS transport and framing but bypasses profiles, sync index, and drift tracking. Recorded separately in run history.

## Requirements covered

- FR-SM-6: Quick-send — transfer file(s) to peer without creating a profile
- FR-DT-1: Whole-file granularity (reuses same FileData framing)
- FR-FH-7: Atomic writes (reuses receive_and_write_file)
- NFR-SEC-1/2: Only paired peers (same TLS mutual auth)

## Protocol

1. Initiator scans source (file or directory tree via walkdir)
2. Sends `RpcRequest::QuickSend { transfer_id, destination_dir, entries: Vec<QuickSendEntry> }`
3. Responder validates destination, sends `RpcResponse::Ok` (ready signal)
4. Initiator streams FileData frames for each non-dir entry (empty frame = EOF per file)
5. Responder writes each file atomically via `receive_and_write_file`
6. Responder sends `RpcResponse::QuickSendAck { transfer_id, files_written }`

## Schema

New `quick_send_records` table (migration v6) — avoids the FK constraint on run_records.profile_id:

| Column | Type | Notes |
|--------|------|-------|
| id | TEXT PK | UUID |
| peer_id | TEXT | who we sent to/received from |
| direction | TEXT | 'send' or 'receive' |
| destination_dir | TEXT | where files landed |
| started_at | TEXT | ISO timestamp |
| finished_at | TEXT | ISO timestamp |
| status | TEXT | success/partial/failed |
| files_transferred | INTEGER | count |
| bytes_transferred | INTEGER | total bytes |
| error_summary | TEXT | nullable |

## Design decisions

- Separate table vs nullable profile_id: chose separate table because SQLite can't ALTER COLUMN to drop NOT NULL, and conceptually quick-sends are a different entity (no index, no drift, no anchors).
- No session required: handler processes QuickSend without StartSession, unlike profile sync. This keeps the protocol sessionless for one-shot transfers.
- walkdir for recursive scanning: already a workspace dependency, keeps the manifest building simple.
